Kohonen Self-Organising Map

Tarun Bonu · September 2026

The three questions

Could the code be made more efficient?

YES

Removing the nested loops took the large run from 5m 54s to 4.76s. Detail below.

Is the code best structured for later use by other developers and in anticipation of productionisation?

NO

Everything is in one file and one function, with no comments, no config, no checks and no tests.

How would you approach productionising this application?

  • First improve the code structure so that it can be easily interpreted and be made modular
  • Add error handling and logging
  • Improve efficiency

Initial thoughts, as soon as I looked at the code

  1. Missing comments
  2. Modularity
  3. Bad variable usage
  4. The mathematical terminologies are not good. When editing code they cannot be typed on the keyboard. These should come from a Python package instead, math.
  5. Need a config file with all the constants in it
  6. No test cases
  7. No guardrails or checks involved
  8. Need Docker and a virtual environment for packages

Implemented, in this order

  1. Good formatting in terms of a repo structure, adding a README
  2. Requirements.txt, virtual environment, gitignore
  3. Performance analysis, benchmarking (100 iterations 0.47s, 1000 iterations 5m 54s)
  4. Better variables and better notations for mathematical equations
  5. Constants added to a config
  6. Addition of modularity, to use the training method as a function call
  7. Added comments to make the code more readable
  8. Addition of logs to print the training progress (also very useful to debug and track errors)
  9. Error handling for any failures

Improving efficiency of the training iterations

Three things I considered:

  1. Some nested loop structure could be avoided
  2. Multi-threading for node-level calculations (rejected, the GIL blocks any gain on pure Python arithmetic)
  3. Using matrix operations to optimise

Performed one change: removal of the loops. Instead of updating nodes one at a time, I now update them through a vector operation.

Before

for x in range(width):
    for y in range(height):
        di = np.sqrt(((x - bmu_x) ** 2)
                     + ((y - bmu_y) ** 2))
        θt = np.exp(-(di ** 2) / (2*(σt ** 2)))
        weights[x, y] += αt * θt * (
            vt - weights[x, y])

After

# whole grid in one operation
distance_squared = (
    (x_coords[:, np.newaxis] - bmu_x) ** 2
    + (y_coords[np.newaxis, :] - bmu_y) ** 2
)
influence = np.exp(
    -distance_squared / (2 * sigma_t ** 2))

weights += (
    (alpha_t * influence)[:, :, np.newaxis]
    * (input_vector - weights))

Just this one change boosted performance:

100 iterations, 10 × 10 grid
0.47s→0.03s
1000 iterations, 100 × 100 grid
5m 54s→4.76s
